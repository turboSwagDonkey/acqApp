# acqApp tests

```
acqApp\.venv\Scripts\python.exe acqApp\tests\run_all.py          # everything
acqApp\.venv\Scripts\python.exe acqApp\tests\run_all.py -v       # full output
acqApp\.venv\Scripts\python.exe acqApp\tests\run_all.py session  # one test
```

Everything runs in **Emulate mode against fakes** — no rig hardware, no windows
on screen, no reaching for real hardware, ~30 s for the set. Each test is also
runnable on its own.

Plain scripts, not pytest: pytest is not in `requirements.txt` and the rig
machine installs only what's there. `run_all.py` gives each test its own process
(most of them build a `QApplication`, and tearing one down and rebuilding it in
a single process is not reliable) and prints a summary.

## What each one defends

| test | guards |
|---|---|
| `test_console_safety` | A diagnostic print containing `→` / `≤` / `⚠` raises `UnicodeEncodeError` on a non-UTF-8 console. Those prints sit inside the acquisition loops, so it surfaces as a *device failure* — the camera just doesn't start. Checks every entry point calls `enable_safe_console()`, and that the real path survives a forced cp1252 console. |
| `test_undefined_names` | Splitting a file leaves the new module missing a name the moved code used — a `NameError` on a path nothing in this suite calls, so everything imports, everything compiles and 454 checks stay green. That happened on 2026-08-13 (six names, out of `devices/stage/settings.py` and `devices/dmd/control.py`) and was caught both times by a throwaway checker. This is that checker, kept: `symtable` resolves each name as the interpreter would, then it asks whether what's left is a module binding or a builtin. Nothing is imported or executed. Controls in three layers — eight breakages it must catch, thirteen valid scopings (closure, `global`, walrus, `try/except ImportError`, class body) it must stay quiet about, and the faithful one: drop a real used import from each of the seven files split that day and require the scan to name it, paired against the unmodified file being clean. Boundary, also asserted: under `from __future__ import annotations` annotations are strings, so an annotation-only import is not defended (`adapters/base.py`'s `Any`). |
| `test_pupil_fits` | The three fits at the bottom of the pupil pipeline, as pure functions. A fit that is 3 px out still draws a plausible circle on the preview and only shows up as noise in an analysis months later. Checks each on geometry it must reproduce exactly, then on the property it was *chosen* for, each with a control that fails that property: Taubin vs a Kåsa fit on a noisy 45° arc, robust vs plain on an eyelash-contaminated ring, and that the ellipse's angle belongs to its semi-major axis. No Qt, <1 s. |
| `test_pupil_limit` | **Where the tracker may look — the region, and the directions.** The animal is head-fixed, so the eye lives in one part of the frame and everything else dark in IR is larger than the pupil; that is why auto-seeding never worked here (`coarse_seed` saw a dark mask over half the sensor and bailed at its own guard). The user-set region bounds the seed and refuses a fit centred outside it. Controls that fail without it: the unrestricted seed gives up on the rig's framing, and prefers a bigger decoy blob when it doesn't. Also that the crop done for speed doesn't shift the answer, that a placement writes back as **one** settings change (three would drop the annulus lock three times), and that a click outside is refused rather than seeding a search that can only fail. The second half is `lid_sectors()`: where a lid crosses the pupil the rays find the *lid's* edge and those points enter the fit like any other — two thirds of the ray failures on the rig clip. It measures the sectors from a run of fits, with the control that matters most — **an evenly-tracked ring must yield no sectors at all**, or the detector could "work" by always excluding something. Records the trap the region inherits: draw it tight around the pupil and the >50 %-dark guard fires inside the circle instead. |
| `test_readout_fps` | The datasheet rate behind every pre-Start label and the initial buffer sizing: a table lookup with log-log interpolation, two clamps and a binning divisor. #11 was this going unnoticed — the panel dropped `link`, the estimate switched columns, and a USB3 rig was told 115 fps instead of 15.7. |
| `test_encoder_derive` | The encoder channel carries single-turn *position*, so every revolution contains a step that isn't motion — and the reset smears across a few samples, each sub-step too small for a half-turn unwrap to catch. Without the speed-based rejection, distance sawtooths back once per turn and a long run under-reports by every revolution in it, invisibly. Runs a synthetic wheel at a known rate past two controls (a raw integrator and a plain unwrap) that both lose all 9 revolutions. |
| `test_dmd` | The DMD used to `print("stub")` and emit `pattern_started`, so a session could record a stimulus stream, write DMD settings into the file, and project nothing — with the panel looking exactly as it does when it works. Drives the real `DmdController` against a fake ALP that records every vendor call, checking the sequence, the frame buffer handed to `SeqPut`, the on-time clamp at the ALP's 10 s limit, and that the mock and real controllers bracket a projection identically in `/dmd`. The other half is `alp.build_frame` geometry, pinning the conventions inherited from `dmdGUI_project` — the >127 threshold, clockwise-positive rotation (checked with an off-centre mark, which is the only way that error shows), and an offset from the panel centre. |
| `test_device_contracts` | Every instrument ships as a real/mock pair, and the `adapters/` adapters read whichever Emulate built. That contract used to be nine `getattr`/`hasattr` probes, so `getattr(c, "device_name", "none")` would file a session that really projected as one that didn't, the moment a mock drifted. `acq/devices.py` writes the contract down — but the rig installs `requirements.txt` and no type checker, so a Protocol nobody asserts catches nothing. This asserts it: each twin satisfies the protocol its adapter reads it through (checked on the *class*, never by constructing a driver), the pairs' public APIs match bar an explicit allowlist, and the probes are gone from every file in `adapters/`. The same idea then runs the other way: `ModuleHost` is what an adapter may ask of the window, and both halves are checked — that `MainWindow` still provides all nine, and that no `self.win.X` anywhere in `adapters/` reaches past them. That second half is what a Protocol alone cannot see, and it is the one that stops the two files quietly becoming one; the surface had already drifted from the seven its docstring claimed. Controls: a stand-in missing only `on_pixels` must fail, a host missing only `signal_sources` must fail, a reach into `win._save_panel` must be caught, and the source searches run over stripped code — the replacement code explains itself by naming the old probes, and a raw-text search read that prose as the thing it warns about (twice: once for comments, once for the docstring naming `self.win.X`). |
| `test_closed_loop` | Phase 5: a rule that actuates from a live signal. `LoopRule` is driven over a synthetic trace past a control with every gate removed — ungated, the same trace fires **3200** times where the real rule fires 4, which is what the hold/refractory/retrigger gates prevent. Also that a source which isn't running reads as `None` and never satisfies `below` (with a real `0.0` as the control), that `snapshot()` is non-consuming — measured against a rival `get_latest()` thread that halves what the display receives — and that the recorded wheel speed lags the live one by ~1.15 s, which is why the panel offers both. Ends with the whole app: arm a rule, record, and check the puffer fired through the trigger bus and `/closed_loop` carries one entry per fire on the session clock. |
| `test_routines` | **Experiment routines — the first feature whose purpose is to actuate.** A protocol runs the stage and the projector with nobody watching each step, so the whole engine takes its actuation as callables and is driven here against a fake rig on a fake clock. The operator's four decisions are each a check: a step ends on the unit it was *given* (the control is a camera off its nominal rate — a converting engine stops the 1.5 s step at 159 frames where this one stops at 147); a stage target outside the soft limits is refused at validation, not at step 7 of 12; a fault **pauses** rather than aborts, keeping the half-finished step's data marked `interrupted` with its file boundary closed, and resume repeats that step as attempt 2; and every per-step file carries the session origin plus its own t0 on the shared clock, because a folder of files that each restarted from zero is unrecoverable once the animal is off the rig. Also the rule with a sample under the objective: the light is never on while the stage is told to move. No Qt, <1 s. |
| `test_encoder_timing` | Speed is a slope, so scheduler jitter in the old `time.sleep`-paced read loop went straight into the wheel speed. The samples now come off the board's sample clock — which creates the camera's batching problem in a new place, so the worker anchors the first block and spaces the rest by the board's rate. Drives the real worker against a fake NI board that delivers correctly clocked samples at irregular times; the control is the arrival times of those same samples (±90 ms of jitter that no longer reaches the file). Also checks the no-timing-engine fallback still acquires *and* reports itself as software-timed. |
| `test_pupil_tracking_thread` | Tracking is unbounded work (a degenerate mask costs ~100–200 ms in `coarse_seed`) and used to run in the 30 Hz display tick, freezing the window — including the voltage camera's preview, which shares that tick. Checks the pupil is still found, that the result is published with the frame it was fitted from, that a panel edit crosses the thread boundary, and that display-side reads stay fast while a deliberately slow tracker grinds — with a control paying the old inline cost. |
| `test_save_paths` | The filename template is free text, so `{subject}` alone resolves every recording of the day to one path — and the writer used to open it with mode `"w"`. Checks token substitution/sanitisation, that `resolve(unique=True)` never returns an occupied path, and that `HDF5Writer.open()` raises rather than truncating an existing session file. No Qt, <1 s. |
| `test_writer_chunks` | The writer hands HDF5 the frame's own buffer where a frame is exactly one chunk (2026-08-24: 1304 -> 2696 MB/s, which is what took bin-1 recording from 53 % of its frames to 100 %). That write converts nothing, so `_writable_chunk` — shape, dtype and C-contiguity — is the entire safety of it. Checks the round trip is byte-identical, that the direct path is really the one being taken (or the round trips prove nothing), that a frame the guard rejects still lands via the slice fallback, and that compression and multi-frame chunks switch the path off. The control is what bypassing the guard costs, and it is worse than corruption: an undersized chunk write returns cleanly, closes cleanly, and then **kills the process that reads the file** with an access violation — so that one runs in a child process, because in-process it takes the suite down with it. No Qt, ~2 s. |
| `test_stage_state` | Motion commands on a disconnected stage must raise `StageControllerError`, not `AttributeError`. Also that `save_axis_updates()` survives a missing or corrupt calibration file — the callers mutate the live axes first and `establish_frame()` has already driven both hard limits, so a raise there loses a just-measured origin. Redirects `config_path()` at a temp file and asserts the operator's real calibration was untouched. |
| `test_stage_panel` | The panel's motion handlers and the panic path, which nothing else here pressed — the GUI tests build the panel but never click it. On 2026-08-13 that let eight controller calls sit unguarded, `_stop`, `_stop_all` and the calibration dialog's `_stop_all` among them: that is Esc → STOP ALL, app-wide, a dead serial link is exactly when it is pressed, and an exception escaping a Qt slot aborts the process — so the abort button could kill the app at the one moment it is needed. Drives the real `SettingsPanel` against a fake controller twice, healthy and with every call raising, checking dispatch, jog sign/step, that a move past `confirm_move_um` asks first and No cancels it, and that no handler lets an exception out. Controls: the old unguarded bodies run on the same controller must still raise, jog must stay enabled when absolute go-to is disabled, and an unbound panel must be a silent no-op. Redirects `config_path()` and asserts the operator's real calibration was neither written nor touched. |
| `test_camera_timestamps` | The camera reads frames in batches. Stamping them on arrival gave every frame in a batch the same time, quantising the recorded timebase to the read cadence instead of the frame rate. Drives the real worker against a fake batching camera and checks intervals track the frame rate, and that a dropped frame shows up in `voltage_cam_index`. |
| `test_module_subsets` | Any combination of instruments can be loaded, so each `ModuleAdapter` has to cope with its neighbours being absent — including the voltage camera, which owns the central view. Builds a window per subset, runs a session, toggles Emulate. Also that teardown survives one module failing to stop: stopping touches hardware, and `_stop_session` stops every adapter in one loop — unguarded, the first raise stranded every module after it with its worker thread running, skipped `stop_all()` so the clock and trigger bus stayed alive while the UI said "Stopped", and through `closeEvent` skipped the DCAM handle close, which is the native crash the pre-init note describes. The control runs the same failure through the old unguarded loop and asserts it reaches nothing. |
| `test_module_hotload` | Loading and unloading instruments **without restarting** (2026-08-25): the sidebar's Modules button, via `MainWindow.set_modules`. Two things make it harder than it looks. Everything a module put on the window has to come back off — settings tab, Signals tab, docks, and its pyqtgraph views, that last one silently, since `setCentralWidget` DELETES the old central widget and a view left in `_pg_views` is a dangling C++ object that takes the process down on the next theme toggle, with no traceback. And `config.MODULES` order is load-bearing — `closed_loop` must stay last so every source-providing adapter exists before its panel asks what is on offer, so a module loaded later has to sort into place, not append. Checks both, that a module loaded into a RUNNING session builds and starts its own worker (nothing calls `_start_session` again for it) and an unloaded one is stopped rather than abandoned, that the centre pane follows its owner but is not rebuilt when nothing moved, and that the whole thing is refused while recording — with the control that the same change succeeds once the recorder is gone. ~6 s. |
| `test_recording_losses` | The three quiet ways a sample fails to reach the file: the ring buffer's count cap evicting the sparse zero-byte events the byte cap protects; samples arriving after the file closed (a worker still inside its callback when the sinks were detached) going uncounted; and a failing `wait_for_frame` retrying with no pause and no message. Includes a control that reproduces the old eviction rule losing the event, and measures the retry rate against an unpaced loop. |
| `test_settings_persistence` | A real restart: edit all seven panels, close the window, build a second one and read them back. Only the camera and Save tabs used to persist, so the wheel's V/rev and diameter — the constants that scale every wheel number in a session file — reset to defaults every launch and were recorded as though measured. Also asserts the stage section stays `port`/`poll_hz` only, and that the LED is *not* restored on. |
| `test_session_recording` | The broad net: full session → record → stop → verify the HDF5. Every expected stream present, timestamps monotonic and trimmed, metadata written (including the close-time attributes), and the puffer panel's channel/duration actually reaching the hardware. |

## Two things to know before adding a test

**Isolate user state — including the hardware.** `isolate_user_state()` also
stands refusing stubs in front of the vendor drivers (`block_real_devices`).
`test_module_subsets` toggles **Emulate off**, which rebuilds the *real* output
controllers; on a laptop with nothing attached that never mattered, but the DMD
is now plugged into this machine and the suite really was opening it, and on the
rig that same toggle would open a DO task on the puffer's line with an animal in
front of it. A test must not be able to reach hardware by accident. Tests that
deliberately drive a fake device install their own module instead
(`test_encoder_timing`, `test_dmd`).

The GUI tests drive the *real* `MainWindow`, which
persists things as a side effect of ordinary use: the Save tab rewrites
`acqapp_local.json` on every field edit, and closing the window writes the dock
layout to `QSettings`. Any test that builds a window must call
`_harness.isolate_user_state()` first, or it will silently overwrite the
operator's save folder, subject ID and panel arrangement. `test_session_recording`
asserts this redirection actually happened, so a regression in the harness is
caught rather than assumed. The same care applies outside `acqapp_local.json`:
the stage calibration is shared with the standalone `stage_control/` app, so
`test_stage_state` repoints `stage.settings.config_path()` at a temp file and
then asserts the real one's mtime never moved.

**Include a control where the test could be vacuous.** `test_camera_timestamps`
re-runs the identical fake camera through the old arrival-stamping behaviour and
asserts it *fails* the same checks; `test_console_safety` asserts the unhardened
path still dies on cp1252. Without those, both tests would keep passing if the
condition they detect quietly stopped being reachable.

## Not covered

These test logic against fakes. They cannot tell you that DCAM populates
`timestamp_us` on the real ORCA-Fire, that the NI lines are wired to what the
config says, or that the stage's serial framing matches the firmware. Those need
the rig — start the app with one module ticked and press **Free run** to bring
on its own.

The DMD is the exception so far: `test_dmd` covers the call sequence and the
geometry, and the same path has additionally been run against the real ALP-4.2
(open → render → upload → project → halt → release, 2026-08-12). What is still
unverified there is optical, not electrical: that the projected square lands
where the settings say it does on the sample.
